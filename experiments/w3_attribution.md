# W3 归因对照：提升来自 harness，还是换一个更强的模型？

> 本报告全部数字来自确定性模拟器 `SeededBackend`，30 个版本化 seed，零第三方依赖、零 API 成本。**它不是真实模型实验**，口径边界见最后一节。

## 一句话结论

在 W3 的参考点 `fpm=60` 上，护栏全关的 `pass^k` 是 0.1433；**不换模型、只开四条护栏**得到 0.3000（+0.1567）；而把模型的输出故障率一路降到 `0`（`fpm=0`）也只能得到 0.2000（+0.0567）。

**只靠降低模型故障率无法达到 `0.3000`**：`off` 整条曲线的上界只有 0.2000（在 fpm=0），缺口 0.1000。换模型路径最多兑现 36.2% 的 harness 收益。

## 实验设计

2 × 8 全因子：模型轴 `fpm ∈ {0, 10, 20, 30, 40, 60, 80, 100}` × 护栏轴 `{off, all4}` × 30 个 seed，共 480 行证据。

| 项 | 取值 |
| --- | --- |
| 后端 | `SeededBackend`（确定性），任务集 `tasks/mvp_10.jsonl` |
| k | 3（主指标 `pass^k`） |
| seed 集 | 直接复用 `eval/robustness.py` 的版本化常量，本次 30 个整数，人为选定、非随机抽样 |
| 模型轴 | `[seeded].fault_per_mille`，只改输出级故障率 |
| 护栏轴 | `[guards].enabled`：`off` = 空；`all4` = `schema_validation`, `idempotency`, `tool_retry`, `json_recovery` |
| 判分 | 终态逐字段 diff + 策略检查 + 必要告知，全部满足才计 1 |

**这是因子实验，不是 A/B**：表内每条横向边（同 fpm、只改护栏）与纵向边（同护栏、只改 fpm）各自是单变量；**同时改两格的格子不能直接对比作因果结论**。W3 的单变量 A/B 证据仍在 `w3_robustness.md` 与 `w3_tool_retry_sweep.md` / `w3_json_recovery_sweep.md`。

### 为什么模型轴是干净的

`SeededBackend._rng` 由 `(seed, task_id, trial, cursor)` 经 SHA256 派生，**不含 fpm**；`_pick_fault` 判定 `rng.randrange(1000) >= fpm` 时输出干净动作。所以每个随机流位点有一个固定的 0..999 阈值，降 fpm 只会删掉一部分故障，不会改变其余故障的类型或位置。下表取 10 个任务 × 3 个 trial × 12 个 cursor = 360 个位点（seed=11），用后端同源的 RNG 实测：

| fpm | 会注入故障的位点数 | 较上一档新增 | 位点示例（前 3 个） |
| --- | --- | --- | --- |
| 0 | 0 | +0 | （空） |
| 10 | 1 | +1 | T09:3:11 |
| 20 | 3 | +2 | T05:2:0, T09:3:11, T10:1:10 |
| 30 | 7 | +4 | T01:2:2, T03:1:3, T03:3:7 |
| 40 | 9 | +2 | T01:2:2, T03:1:3, T03:3:7 |
| 60 | 21 | +12 | T01:2:2, T02:1:4, T03:1:3 |
| 80 | 28 | +7 | T01:2:2, T01:3:1, T02:1:4 |
| 100 | 44 | +16 | T01:1:6, T01:1:7, T01:2:1 |

低 fpm 的故障位点集合是否为高 fpm 的子集、计数是否单调不减：**是**。因此「降 fpm」在本模拟器里严格等价于「同一模型少犯输出级错误」，是单变量轴；它**不**等价下文口径边界里列出的模型推理 / 理解能力。

## 两条曲线

| fpm（‰） | `off` `pass^k` | `off` min~max | `all4` `pass^k` | `all4` min~max | Δ（护栏收益） |
| --- | --- | --- | --- | --- | --- |
| 0 | 0.2000 | 0.20~0.20 | 0.3000 | 0.30~0.30 | +0.1000 |
| 10 | 0.1867 | 0.10~0.20 | 0.3000 | 0.30~0.30 | +0.1133 |
| 20 | 0.1733 | 0.10~0.20 | 0.3000 | 0.30~0.30 | +0.1267 |
| 30 | 0.1567 | 0.10~0.20 | 0.3000 | 0.30~0.30 | +0.1433 |
| 40 | 0.1533 | 0.10~0.20 | 0.3000 | 0.30~0.30 | +0.1467 |
| 60 | 0.1433 | 0.10~0.20 | 0.3000 | 0.30~0.30 | +0.1567 |
| 80 | 0.1267 | 0.00~0.20 | 0.3000 | 0.30~0.30 | +0.1733 |
| 100 | 0.1067 | 0.00~0.20 | 0.3000 | 0.30~0.30 | +0.1933 |

- **`off` 曲线随模型变可靠而上升，但有天花板**：fpm 从 100 降到 0，`pass^k` 从 0.1067 变为 0.2000；按 fpm 从低到高是否单调不增：**是**。这个上界由 7 条脚本固有缺陷任务锁死，清单见 [可达上限分析](w3_ceiling.md)。
- **`all4` 曲线全程平坦**：各档 `pass^k` 均为 0.3000，说明四条护栏把注入故障完全吸收，模型轴不再影响结果。
- **护栏收益随模型变强而收窄但不归零**：fpm=100 时 Δ=+0.1933，fpm=0 时 Δ=+0.1000。后者是护栏在「零注入故障」下仍修好的脚本固有缺陷（T03 重复写），不在模型轴的作用范围内。

## 收益拆分

| 路径 | 起点 → 终点 | Δ`pass^k` |
| --- | --- | --- |
| 只换模型（降故障率） | `off`@60 0.1433 → `off`@0 0.2000 | +0.0567 |
| 只加 harness | `off`@60 0.1433 → `all4`@60 0.3000 | +0.1567 |
| 零故障下护栏的残余收益 | `off`@0 0.2000 → `all4`@0 0.3000 | +0.1000 |
| 换模型路径够不到的部分 | `all4`@60 − `off`@0 | +0.1000 |

因为护栏曲线平坦，恒等式 `harness_path = model_path + (all4@0 − off@0)` 成立（实测 **是**）：加护栏的收益可以完整拆成「等价消除全部注入故障」+「额外修好一个脚本固有缺陷」。

**必须点破的一点**：`0.30 > 0.20` 的那 0.10 来自 `idempotency` 修了 T03 脚本里固有的重复退款（W3 已钉死，见 [w3_ceiling.md](w3_ceiling.md)）。它不是「harness 普遍强于更强模型」的证明——真实模型完全可能自己不重复退款。这里能成立的只有一句：*在本模拟器的这条模型轴上*，降低故障率够不到加护栏的水平，因为这条轴不动脚本固有缺陷。

## 口径边界（不得省略）

1. **fpm 不是「模型能力」的全部**。它只控制四类*输出级*故障（坏 JSON / 错参数 / 错工具 / 重复写）的注入率，不模拟推理、语言理解、工具规划、多轮追问或长上下文能力。把降 fpm 叫作「换更强的模型」是本实验内部的类比，**不能外推到任何真实模型**。
2. **`fpm=0` 不是「完美模型」**。从证据自动推导的 7 条恒失败任务（脚本固有缺陷：坏 JSON、缺参数、错工具、无 final、超退、少说必要告知）原样保留，所以 `off` 曲线被 fixture 锁死在 0.2000。这个天花板是任务集属性，不是模型属性；清单见 [w3_ceiling.md](w3_ceiling.md)。
3. **不替代 W4**。真实模型是否在 `[GUARD-REJECT]` 下改对、以及成本 / 延迟帕累托，都没在这里测；W4 接真实模型前仍需先定 API 预算。本报告只把对照设计与口径先在零成本模拟器上跑通。
4. **分辨率仍是 0.10**。`pass^k = passk_hits / 10`，所有均值都落在 1/10 的格点组合上，表里的 +0.0567 / +0.1567 是 30 个 seed 的平均，**不是连续效应量**；见 [w3_resolution.md](w3_resolution.md)。
5. **因子实验不是 A/B**。跨 fpm 又跨护栏的两格对比不作因果解读；W3 的单变量因果证据仍以 `w3_robustness.md` 与各 `*_sweep.md` 为准。
6. 全程是本地后端的确定性（无网络、无时钟、无全局随机），token / 延迟恒 0，不构成任何成本或延迟结论；`invalid_calls` 同样不是成功率的代理指标。

## 数据来源与复现

每行一档 fpm、一个 seed、一格的完整指标（seed / fpm / cell / guards / pass¹ / pass^k / passk_hits / task_count / trial_count / 逐任务 0/1 序列）在 `w3_attribution.jsonl`；既有单变量 A/B 留档在 `experiments/runs/<run_id>/`。

```
python -m eval.attribution
python -m eval.attribution --from-jsonl
python -m unittest discover -s tests -v
```

本模块不新增护栏、不加配置字段、不改判分口径、不修改任何既有留档；跑批只写共用临时目录，不读时钟 / 环境变量、不用全局随机、零第三方依赖，同命令两次产物逐字节一致。
