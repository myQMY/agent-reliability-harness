# W4-c 前置：干净动作留档与判定尺子离线校准（零成本、零网络）

> 由 `python -m eval.w4c_probe --dry-run` 生成。**全程没有发起任何模型 API 请求，
> 没有花一分钱，不跑判分、不改任何归档。**
> **这些数字只证明留档与判定链路接得上，不是 W4-c 的实验结论。**
> 校准用的是确定性脚本夹具，不是语言模型；它的判定分布不预示真实模型的结果。

校准输入：`tasks/mvp_10.jsonl`（10 任务 × k=3 = 30 trial、单轮）、`seed=11`、`fault_per_mille=300`，四条护栏全开。

> 校准脚本先按 `eval/w4b_probe.clean_script` 过滤任务集固有缺陷（含成对重复写），只保留合法工具调用。不过滤时 `fpm=60` 会「注入 0 次却数到 7 次拒绝」，那是脚本固有缺陷，不是装置生效。

## 装置是否成立（三路强制断言）

| 路 | 夹具在拒绝后 | 注入次数 | 拒绝事件 | comparable | identical | different | missing |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `fpm=0` 基准 | 给不同动作 | 0 | 0 | 0 | 0 | 0 | 0 |
| A：给不同动作 | 固定的另一个合法读工具调用 | 16 | 16 | 13 | 0 | 13 | 0 |
| B：重发同一动作 | 返回上一次被替换的干净动作 | 16 | 16 | 13 | 13 | 0 | 0 |

- `fpm=0` 基准必须 0 注入 / 0 拒绝 / 0 留档，否则「分母只来自注入」不成立。
- A 路把全部可比事件判为 `different`（`identical = 0`）；B 路把全部可比事件判为 `identical`。两路一起证明尺子既不误报也不漏报。
- 两路 `missing` 必须为 0：每个由注入造成的拒绝都能配回一份干净动作留档。
- `idempotency_skipped` / `chained` 按口径单列、不进主分母，B 路里出现它们是脚本夹具的机械性质，不是装置故障。

## 防代答红线（本组成立的前提）

- `clean_text` 只在注入时被读进内存留档，运行时绝不写进 `messages` / system prompt / 拒绝文本，也绝不读它来构造响应；`OutputFaultBackend` 拒绝后照常调用底层真实模型、只跳过注入。
- 留档写在独立 `clean_actions/` 目录，不进 `experiments/runs/` 归档三件、不改 trace 既有 8 字段、结果行、判分或 `run_id`。
- 校准里的「重发同一动作」由夹具产生，只用于检验尺子；真实跑批里没有任何代码替模型重发动作。


## 口径

- **输出被注入扰动，不是纯净模型行为**。`fault_per_mille` 是装置参数，不是模型能力轴；本结果不与 W3 / W4 首轮 / W4-b 的任何数字相减或拼曲线。
- 主分母 `comparable = identical + different + final_instead`；`idempotency_skipped`（拒绝文本要求「跳过该动作」）、`unparseable`、`chained`（连锁拒绝，不是注入直接产生）、`missing` 全部单列、如实统计。
- `identical` 的含义是「模型按同一策略重新推导出了同一个合法调用」，**不是**回忆起被拿走的动作：模型从未见过 `clean_text`，对话里只有坏文本 + 拒绝消息。
- `different` 只说明给了另一个合法动作，不等于改错；`final_instead` 不是重发。
- 本判定不读 `passed`、不进结果行、不改 grader；论效果仍然只认 `pass^k`，而本组 `pass^k` 无分辨率。机制证据不是护栏有效性的证据。
