# W3 `json_recovery` 护栏：单变量 A/B 的跨 seed 证据

> 由 `python -m eval.ab_sweep` 依据 `w3_json_recovery_sweep.jsonl` 如实生成；不含生成时间，同命令两次产物逐字节一致。
> 本模块不新增护栏、不改判分口径、不修改任何既有留档：四份 2×2 配置的 `run_id` / `config.json` / `result_rows.jsonl` / `report.md`、`w3_guard_matrix.md`、`w3_robustness.*` 与冻结基线全部一字节未动。

## 为什么要做这份检查

既有 [多种子稳健性检验](w3_robustness.md) 已经证明：2×2 全因子报告只在 `seed=11` 上跑过一次，10 条任务、k=3，`pass^k` 分辨率 0.10，而换 30 个 seed 后 `schema_validation` 在多数 seed 上完全测不到提升。**`seed=11` 是偏乐观样本**。因此本轮新增护栏不再只报一次 A/B：对照纪律是「同一 seed 集、只差 `[guards].enabled`、附符号分布」。

## 机制：这条护栏到底修了什么

`json_recovery` 覆盖四类注入故障里最后一条没有护栏覆盖的类别：`bad_json`。W1 的 JSON 重试只给出 `RETRY_HINT` 提示，被替换掉的那个动作会被直接跳过；本护栏**保留原提示证据**（grader 据此仍归因 `output_format`），只额外追加一个 `role=guard` 的 span 与一条 `[GUARD-REJECT]` 消息，让 `SeededBackend` 重发那一个干净动作。脚本里固有的连续坏 JSON 没有干净动作可重发，会自然收敛到 `TERMINATION_JSON_FAILURE`，护栏不越界。

| 缺陷 | 既有机制 | `json_recovery` |
| --- | --- | --- |
| `bad_json` | W1 的 JSON 重试只提示、跳过动作 | **唯一能恢复被跳过动作的护栏** |
| `bad_args` | `schema_validation` / `tool_retry` | 不触发：JSON 合法 |
| `wrong_tool` | `tool_retry` | 不触发：JSON 合法 |
| `duplicate_call` | `idempotency` | 不触发：JSON 合法 |

- **格式错误不进入 `tools.call`**，所以 `invalid_calls` 与这条护栏无关；论效果只看 `pass^k`。恢复受共享的 `MAX_GUARD_REJECTIONS` 上限约束，不做真实 sleep，保证逐字节可复现；`grader` 的归因与判分口径不因开关改变。
- **单变量 A/B 会低估这类护栏**：`pass^k` 要求 k 次全过，其他三类注入故障还在时，恢复一个 `bad_json` 往往不产生分数变化。它的价值要在「前三条护栏全开」的组合里才显出来 —— 见 [可达上限分析](w3_ceiling.md)：四条全开把残余 gap 归零，且逐 seed 等于「关掉注入故障 + 四条全开」。

## 口径与限制（读表前先看）

- **不是显著性检验**：没有置信区间、没有 p 值、不做多重比较校正。这里只是把同一套确定性跑批在多个 seed 上重做一遍，报告效应符号分布。
- **seed 是人为选定的一组整数，不是随机抽样**：「N 个里 X 个为正」不能当概率估计，更不能外推到真实模型、其他任务集或其他故障注入率。
- **分辨率极粗**：10 条任务 × k=3，`pass^k` 只能取 0.10 的整数倍；`+0.10` 仅代表「一个任务从不是 k 次全过变成 k 次全过」，不是连续的效应量。
- **全部数字来自确定性模拟器**：`SeededBackend` 没有语言理解能力，注入的是人为噪声；这些数字**不构成任何真实模型能力、成本或延迟结论**，`tokens` / `latency_ms` 恒为 0。
- **护栏拒绝协议只在模拟器里验证过**：`[GUARD-REJECT]` 靠 `_pending_correct` 触发重发干净动作；真实模型能否读懂拒绝消息并改对，必须接 `OpenAIBackend` 后另开实验，本表不能外推。
- 效应只做 `|v| < 1e-9 → 0` 的浮点噪声归零，不做任何四舍五入或结果修饰。
